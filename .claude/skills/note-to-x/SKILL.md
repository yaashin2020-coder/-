# note → X シェア

noteの記事を、Xの投稿文に変換してシェアするためのスキル。

## 手順

### 1. 記事を取得する

優先順に試す。

1. **ユーザーがURLを貼った場合** → `WebFetch` で記事本文・タイトルを取得。
2. **URLがない場合** → `references/config.md` に `note_username` があれば
   `https://note.com/<username>/rss` を取得し、最新記事（先頭の `<item>`）を使う。
   RSSの `content:encoded` に本文HTMLが入っているので要約に使える。
3. **どちらもネットワークで取れない場合**（このenvironmentは外部通信が制限されている
   ことがある。`curl` が exit 56 / CONNECT 403 を返したらそれ）
   → ユーザーに「記事タイトル・本文（または要点）・URL」を貼ってもらう。
   憶測で記事内容を書かない。**書いていないことを投稿文に混ぜるのは厳禁。**

取得できたら、投稿前に必ず「これで投稿していい？」と本文案を見せて確認を取る。
Xへの投稿は取り消しづらい外向きの行為なので、ユーザーの明示的なOKなしに投稿しない。

### 2. 投稿文を作る

`references/style.md` にユーザーの好みの型がある場合はそれに従う。ない場合の既定：

```
<記事の要点を1〜2文。記事に実際に書かれている内容だけ>

<noteのURL>

#ハッシュタグ #ハッシュタグ
```

制約：

- **280文字**（半角換算。日本語は1文字=2カウント相当ではなく、Xの日本語カウントは
  1文字=2重み → 実質全角140文字が上限）。`scripts/post_to_x.py --count` で正確に測れる。
- **URLは何文字でも23文字分**として計算される（t.co短縮のため）。
- ハッシュタグは2〜3個まで。多いとスパムに見える。
- 記事タイトルをそのまま貼るだけにしない。読んだ人が「読みたい」と思う一文にする。
- 煽り・誇張（「衝撃の」「99%の人が知らない」等）は入れない。

長い記事は**スレッド**にしてもよい。その場合は1投目に要点とURL、2投目以降に補足。

### 3. 投稿する

`scripts/post_to_x.py` を使う。認証情報の有無で自動的に動作が変わる。

```bash
# 文字数チェックだけ
python3 scripts/post_to_x.py --count --text "投稿文"

# 実際に投稿（環境変数に X_API_KEY 等が揃っているとき）
python3 scripts/post_to_x.py --text "投稿文"

# スレッド投稿
python3 scripts/post_to_x.py --text "1投目" --text "2投目"

# 認証情報なし → ワンタップ投稿リンクを出力（ブラウザで開けば下書き状態でXが開く）
python3 scripts/post_to_x.py --intent --text "投稿文"
```

認証情報が未設定なら `--intent` で出力されるURLをユーザーに渡す。これは
`https://x.com/intent/post?text=...` 形式で、開くと本文が入った状態のXの投稿画面に
なる（送信ボタンを押すのはユーザー）。**この方法は認証情報もネットワーク許可も不要。**

セットアップ（APIキー取得・ネットワーク許可）の手順は `references/setup.md` にある。

## やらないこと

- ユーザーの確認なしに投稿する
- 記事に書かれていない内容を投稿文に足す
- 取得できなかった記事の内容を推測で書く
- 同じ記事を重複投稿する（直近の投稿を覚えておく／不明なら聞く）
